# 서버 쪽 코딩 에이전트 설계 (v0.2)

> 작성일: 2026-11-19 · 상태: 설계 (구현 전) · 관련: [PLAN.md](../../PLAN.md) 0장 "딸깍"

## 목표

`agent:go` 라벨이 붙으면 **사용자 저장소에 아무것도 설치하지 않은 채로** Claude가 수정 브랜치를 만들고 Draft PR을 연다. 사용자 쪽 준비물은 우리 GitHub App 설치뿐이다.

## 실행 환경 후보 비교

조사 출처: Claude Managed Agents는 Anthropic 공식 문서 기반 참고 자료, Cloudflare는 공식 문서(Containers, Sandbox SDK, 가격·제한 페이지). 둘 다 2026-11-19 기준.

| | **Claude Managed Agents** | **Cloudflare Containers / Sandbox SDK** |
|---|---|---|
| 개요 | Anthropic이 에이전트 루프와 세션별 컨테이너를 모두 운영 | 우리 Worker가 컨테이너를 띄우고 그 안에서 Claude Code CLI 실행 |
| 상태 | 베타 (`managed-agents-2026-04-01`) | Workers Paid 플랜 필요($5/월). 일부 기능이 public beta로 표시됨 |
| 우리가 만들 것 | 에이전트 설정, 세션 생성, 완료 웹훅 처리 | Docker 이미지(Claude Code 버전 고정), Durable Object 수명 관리, 실행·폴링·정리 코드 |
| 저장소 접근 | `github_repository` 리소스로 저장소를 자동 클론. **토큰은 컨테이너에 들어가지 않고** Anthropic 쪽 git 프록시가 push 시점에 넣어줌 | 직접 clone. 외부로 나가는 HTTPS를 Worker가 가로채서 토큰을 넣는 방식 가능. 문서는 "샌드박스가 가진 토큰은 그 안의 모든 프로세스가 읽을 수 있다"고 경고 |
| 네트워크 제한 | `limited` 네트워킹 + `allowed_hosts` (기본 차단) | `enableInternet: false` + 허용 호스트만 Worker가 중계 |
| 비용 통제 | **세션 예산**(달러 상한)을 플랫폼이 강제 | 직접 구현해야 함 (시간 제한, 강제 종료) |
| 비용 | 토큰 + 세션 실행 시간 **세션-시간당 $0.08** (running 상태만, 밀리초 단위 과금. 공식 가격 페이지 요약 기준, 재확인 필요) | 토큰 + 컨테이너. 5분짜리 작업 1건에 컴퓨팅 약 $0.006 (standard-1 기준 추정, Durable Object 비용 별도). 유휴 시간도 과금되므로 끝나면 바로 정리해야 함 |
| 완료 알림 | 세션 상태 웹훅 (`session.status_idled` 등, Console에서 등록) | 직접 폴링 또는 알림 구현 |
| 모델 | Claude만 | Claude Code를 넣으면 Claude. 다른 CLI로 바꿀 수도 있음 |
| 구독 사용 | 불가 (API 키) | 불가 (서버 실행이므로 API 키) |
| 장점 | 만들 코드가 가장 적고, 토큰 격리와 예산 상한이 기본 제공됨 | 인프라를 Cloudflare 하나로 통일, 세부 제어 가능, 컴퓨팅 비용이 낮음 |
| 단점 | 베타, 실행 시간 과금, 데이터가 Anthropic 세션 기록에 남음(삭제 전까지) | 이미지 관리, 수명 관리, 보안 경계를 직접 책임짐 |

## 결정 (2026-11-19 확정)

**v0.2는 Claude Managed Agents로 시작한다.**

- "딸깍"을 가장 빨리 실제로 보여줄 수 있다. 만들 코드가 가장 적다
- 보안상 가장 중요한 두 가지가 기본으로 들어 있다. 하나는 저장소 토큰이 컨테이너 안에 없다는 것이고, 다른 하나는 세션 예산 상한이다
- 실행기를 인터페이스(`AgentRunner`)로 분리해서, 비용이나 제어 문제가 생기면 Cloudflare Containers 구현을 추가할 수 있게 한다

## 흐름

```
① 메인테이너가 이슈에 agent:go 라벨
② GitHub → 우리 Worker (GitHub App 웹훅, 서명 검증)
③ Worker: 라벨 붙인 사람이 쓰기 권한이 있는지 GitHub API로 확인
   → 라벨을 agent:working으로 교체, Discord 스레드에 "작업 시작"
④ Worker: 이슈 내용을 읽어 Managed Agents 세션 생성
   - 저장소: github_repository 리소스. 토큰은 **해당 저장소 하나, Contents 읽기 전용**으로 발급
   - 네트워크: limited (기본 차단)
   - 예산: 세션당 달러 상한 (기본값은 테넌트 설정)
   - 첫 메시지: 작업 지시 + 이슈 내용 (신뢰하지 않는 데이터로 감싸서)
⑤ Claude가 코드를 수정하고, 변경 사항을 /mnt/session/outputs/에 patch와 요약 파일로 남김
   (에이전트는 push하지 않는다)
⑥ 세션이 끝나면 Anthropic → 우리 Worker (session.status_idled 웹훅)
⑦ Worker: 결과 파일을 받아서 검사
   - .github/ 등 금지 경로를 건드렸거나 형식이 이상하면 거부하고 이슈에 사유 댓글
   - 통과하면 우리 GitHub App으로 커밋을 만들어 feedback-to-pr/issue-N 브랜치에 올리고 Draft PR 생성 ("Fixes #N")
   - 수정 사항이 없으면 에이전트의 설명을 이슈 댓글로
   → 라벨 agent:done / agent:failed, Discord 스레드에 결과
⑧ Worker: 세션 삭제 (API로 기록·이벤트·샌드박스 삭제. 데이터 보관 최소화)
```

**쓰기는 전부 Worker가 한다.** 처음 설계는 에이전트가 직접 push하는 방식이었지만 다음 이유로 바꿨다.
- **토큰 만료**: 세션이 시작된 뒤에는 저장소 리소스의 토큰을 바꿀 수 없다 (공식 문서상 세션 업데이트는 `tools`와 `mcp_servers`만 가능). GitHub App 설치 토큰은 1시간짜리라 긴 작업 중간에 push가 실패할 수 있다. 쓰기를 Worker로 옮기면 세션 토큰은 클론에만 쓰이므로 이 문제가 사라진다
- **보안**: Anthropic 쪽 세션에는 읽기 전용 토큰만 간다. 에이전트가 조종당해도 저장소에 직접 쓸 수 없고, Worker가 변경 내용을 검사한 뒤에만 올라간다
- **통제**: 브랜치 이름, 커밋 작성자, PR 제목·본문 형식을 우리가 정한다. GitHub MCP 서버와 별도 인증(vault)도 필요 없다

## 보안

| 위험 | 대응 |
|---|---|
| 신고 글의 숨은 지시(프롬프트 인젝션) | 사람 승인(`agent:go`) 필수, 쓰기 권한 재확인, 신뢰하지 않는 구간을 데이터로 다루라는 시스템 지시, Draft PR만 생성 |
| 토큰 유출 | 세션에는 **읽기 전용, 저장소 하나** 토큰만 감. 그마저 컨테이너 안이 아니라 Anthropic 쪽 git 프록시가 사용. Anthropic API 키와 쓰기 권한은 Worker에만 있음 |
| 다른 저장소 접근 | 설치 토큰을 해당 저장소 하나로 범위 제한해서 발급 |
| 에이전트가 저장소에 직접 쓰기 | 불가. 쓰기는 Worker가 결과 파일을 검사한 뒤에만 함 |
| 워크플로 파일 변조 | Worker가 `.github/` 변경을 거부 + 우리 앱에 `workflows` 권한을 주지 않음 → 이중 차단 |
| 외부로 데이터 유출 | `limited` 네트워킹, 허용 호스트 최소화 |
| 비용 폭주 | 세션 예산 상한, 테넌트별 월 실행 횟수 제한 |
| 데이터 보관 | 세션 기록은 지우기 전까지 Anthropic에 남는다 → 작업이 끝나면 API로 세션 삭제. 개인정보는 이미 마스킹된 상태로 넘기고, 처리방침에 명시. Managed Agents는 ZDR·HIPAA 대상이 아님 |

## GitHub App 권한 변경

| 권한 | 지금 | v0.2 |
|---|---|---|
| Issues | 읽기·쓰기 | 읽기·쓰기 |
| Metadata | 읽기 | 읽기 |
| **Contents** | 없음 | **읽기·쓰기** (브랜치 푸시, 클론) |
| **Pull requests** | 없음 | **읽기·쓰기** (Draft PR 생성) |
| Workflows | 없음 | **주지 않음** (의도적) |
| 웹훅 이벤트 | 없음 | **Issues** (라벨 이벤트), Installation |

권한이 늘어나면 이미 설치한 사용자는 GitHub에서 새 권한을 승인해야 한다.

## 확인 결과 (2026-11-19, 공식 문서)

| 질문 | 결과 |
|---|---|
| 실행 시간 단가 | **세션-시간당 $0.08**, running 상태만 과금 (가격 페이지 요약 기준, 원문 재확인 필요). 세션 무료 제공량 없음 |
| 사용 가능 여부 | **모든 API 계정에 기본으로 열려 있음**. 대기 명단 없음 |
| 세션 상태 웹훅 | `session.status_idled`, `session.status_terminated`, `session.budget_reached` 등. **등록은 Console에서만** (API 없음). 페이로드에는 종류와 ID만 있어서 세션을 다시 조회해야 함. 재시도 최대 3번, HTTPS 443 포트만 |
| 데이터 보관·삭제 | 지우기 전까지 보관. **API로 삭제 가능** (`DELETE /v1/sessions/{id}`, 기록·이벤트·샌드박스 모두 삭제). 실행 중인 세션은 멈춘 뒤 삭제 |
| 세션 중 토큰 교체 | **불가**. 세션 업데이트는 `tools`, `mcp_servers`만 바꿀 수 있음 → 쓰기를 Worker로 옮긴 이유 |
| 저장소 토큰 종류 | **확인 못 함**. 참고 자료 예시는 개인 토큰(PAT). GitHub App 설치 토큰이 되는지는 실제로 시도해 봐야 함 |
| 세션 최대 시간·유휴 종료 | **확인 못 함**. 샌드박스 상태는 30일 보관된다는 설명만 있음 |

**대안 (설치 토큰이 안 될 경우)**: 저장소를 리소스로 붙이지 않고, Worker가 저장소 압축 파일을 받아 세션 파일로 올린다. 그러면 Anthropic 쪽에 GitHub 토큰이 아예 가지 않는다. 대신 큰 저장소는 느려진다.

## 비용 감각 (추정)

한 건에 세션 10분, 입력·출력 토큰이 수십만 개라고 가정하면:
- 실행 시간: 10분 × $0.08/시간 ≈ **$0.013**
- 토큰 비용이 대부분을 차지한다. 정확한 금액은 실제 작업으로 측정해야 한다
- 세션 예산 상한으로 건당 최대 금액을 고정한다

## 작업 순서 (구현 시)

1. GitHub App 웹훅 수신 (`/github/webhook`, 서명 검증), 라벨 이벤트 처리, 권한 재확인
2. `AgentRunner` 인터페이스와 Managed Agents 구현 (에이전트 1회 생성, 세션 생성, 읽기 전용 토큰, 예산)
3. 세션 완료 웹훅 → 결과 파일 검사 → 커밋·브랜치·Draft PR 또는 댓글 → 세션 삭제
4. 라벨 상태 전이와 Discord 스레드 알림
5. 실제 저장소 테스트 (테스트용 저장소에 일부러 넣은 작은 버그로). 이때 설치 토큰으로 클론이 되는지 먼저 확인
